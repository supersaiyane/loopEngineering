The System

How the Orchestrator Works

A single hook intercepts every prompt, scores it, selects the right mode, activates agents in the right order, and enforces quality gates — fully automatic.

🎯
Step 01

Prompt Interception

Every prompt hits elite-team-orchestrator.kiro.hook on promptSubmit. GUARD 1 reads decisions.md + lessons.md before any processing.

🔬
Step 02

Confidence Scoring

25 signals scored across the prompt. HIGH (≥3) auto-routes. MEDIUM (2 signals) pauses for confirmation. LOW triggers the 7-question Discovery Engine.

🗺️
Step 03

Mode Selection

Discovery scores 0–21 across 7 dimensions and maps to one of 5 execution modes. The mode determines which agents activate and in what order.

⚡
Step 04

Agent Pipeline

Agents activate sequentially by phase. Each reads only the 2–4 skill files relevant to the current story — targeted, not broadcast.

🔒
Step 05

Gate Enforcement

GATE S1 (pre-code security) and GATE S2 (post-code quality + cross-tenant test) block progress if any item fails. No exceptions.

📚
Step 06

Memory + Lessons

Every sprint retro writes to lessons.md with a gate_fired_at timestamp. HIGH-confidence lessons apply at next session start automatically.

Discovery Engine

7 Questions → Right Mode

When confidence is LOW, the system asks 7 structured scoping questions to score the build (0–21) and map to the right execution mode.

  1. What type of product or system are you building? (platform, service, tool, feature)
  2. What is the target scale? (users, requests/sec, data volume)
  3. What is the team size and experience level?
  4. What existing codebase or infrastructure does this integrate with?
  5. What are the compliance or regulatory requirements?
  6. What is the expected timeline and delivery pressure?
  7. Are there security, privacy, or multi-tenancy requirements?

Ponytail Protocol

7-Rung Dependency Ladder

The "lazy senior dev" principle — climb from the cheapest rung before reaching for a heavier one. Rung disqualification triggers an ADR and a same-rung alternative check.

Rung 1 — Cheapest

Standard Library

Language built-ins and stdlib first. No external deps if stdlib covers it.

Rung 2

Well-Known Dependency

Battle-tested package: >1M weekly downloads, active maintenance, low CVE history.

Rung 3

Configuration / Flag

A config flag or env var achieves the goal without adding code or a new package.

Rung 4

Existing Internal Tool

Something already in the codebase or org toolchain that does this or close to it.

Rung 5

Compose Existing Tools

Combine two existing tools rather than adding a new dependency.

Rung 6

Fork + Patch

Fork the dependency, apply the minimal patch, own the diff. Only if Rungs 1–5 fail.

Rung 7 — Most Expensive

Write Custom

Build from scratch. Requires explicit ADR, security sign-off, and maintenance plan.

Security & Quality

Gates & Guards

Non-negotiable checkpoints. A failed gate blocks the pipeline completely — no exceptions, no "ship and fix later."

GATE S1 — Pre-Code

Security Check

  • STRIDE threat model complete
  • Auth + authz model reviewed & approved
  • Secrets management plan in place
  • OWASP Top-10 reviewed
  • Compliance ADRs signed
  • No code written until this PASSES
GATE S2 — Post-Code

Quality + Security

  • SAST scan clean
  • OWASP re-verified on shipped code
  • No secrets committed
  • Ponytail audit PASS
  • Cross-tenant access-denial test ✓ (Fix 43C)
  • Jira comment with gate summary
GUARD 1 — Always Active

Constraint Drift Guard

  • Reads decisions.md at EVERY session start
  • HIGH-confidence lessons apply immediately
  • Checks gate_fired_at timestamp (Fix 43A)
  • Absent gate_fired_at → Sprint 0 treatment
  • Architecture decisions bind ALL roles
GUARD 2 — Always Active

Bad Loop Guard

  • Requires BOTH: domain keyword + high-risk verb
  • Self-triggering: deploy / release / production
  • Blocked domains: auth, payments, user-data, secrets
  • Blocked verbs: delete, wipe, drop, overwrite, bypass
  • Fires before any code execution
GUARD 3 — Always Active

Image Exact-String Guard

  • Intercepts image-compressed context reads
  • Exact strings (SHAs, camelCase IDs, file:line refs) must be re-verified
  • 11–17% silent misread rate found in production before this guard
  • Semantic content safe (97–98% recall); exact strings are not
  • Zero undetected misreads post-implementation (44 fix cycles)

This paper begins from that gap and presents the Loop Engineering Framework as a principled process-layer response — documented across 44 fix cycles, 12 classified failure modes, and a novel compression-fidelity bifurcation finding.
