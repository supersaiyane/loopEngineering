How work moves

From request to verified work

This is the intended flow. The selected mode, host permissions and actual evidence determine what happens in a particular run.

  1. 01 · ROUTEUser request and context

    For a new build, ask seven discovery questions unless skipped; preserve unknown answers. Recommend a mode and offer model choice.

  2. 02 · SELECTChoose a proportionate mode

    Full for a broad project; focused or direct for smaller work; hybrid for an existing host spec; lean for a smaller build. Your choice takes precedence.

  3. 03 · THINKResearch → CTO → strategy review

    In the full flow, market research informs strategy and a review before product planning begins.

  4. 04 · DESIGNProduct manager → architect → specialists

    Shape requirements and architecture, then bring in database, cloud, FinOps and security expertise as applicable.

  5. 05 · BUILDPlan → do → check → act

    The scrum master plans stories. Relevant engineering, QA, security and operations roles contribute and review work.

  6. 06 · RECORDVerify, record and continue

    Record actual checks and handoffs; update the tracker, cumulative graph, reports and checkpoint when applicable.

Specialists join where needed. A platform with AI may bring in AI engineering, RAG, data, safety, learning or privacy roles alongside the main team. They do not all run in sequence. Focused and direct modes can skip the full project chain.

Discovery Engine

7 Questions → Right Mode

For a new build, discovery asks seven questions unless skipped. The score is a recommendation, not a reliability measure; Mode 2 is selected for focused work.

  1. Platform — What kind of application are you building?
  2. Scale — Who is it for and how many users will it serve?
  3. Complexity — How many features and integrations are needed?
  4. Deployment — Where will the application run?
  5. Revenue — What is the business or monetization model?
  6. Design and UX — What level of visual polish is needed?
  7. Security and compliance — What protection and regulatory requirements apply?

Ponytail Protocol

7-Rung Dependency Ladder

The "lazy senior dev" principle — climb from the cheapest rung before reaching for a heavier one. Rung disqualification triggers an ADR and a same-rung alternative check.

Rung 1 — Cheapest

Standard Library

Language built-ins and stdlib first. No external deps if stdlib covers it.

Rung 2

Well-Known Dependency

Battle-tested package: >1M weekly downloads, active maintenance, low CVE history.

Rung 3

Configuration / Flag

A config flag or env var achieves the goal without adding code or a new package.

Rung 4

Existing Internal Tool

Something already in the codebase or org toolchain that does this or close to it.

Rung 5

Compose Existing Tools

Combine two existing tools rather than adding a new dependency.

Rung 6

Fork + Patch

Fork the dependency, apply the minimal patch, own the diff. Only if Rungs 1–5 fail.

Rung 7 — Most Expensive

Write Custom

Build from scratch. Requires explicit ADR, security sign-off, and maintenance plan.

Security & Quality

Gates & Guards

Review guidance describes security and quality checkpoints. Prompt-based gates are not an independent permission boundary; inspect the actual checks and host controls.

GATE S1 — Pre-Code

Security Check

  • STRIDE threat model complete
  • Auth + authz model reviewed & approved
  • Secrets management plan in place
  • OWASP Top-10 reviewed
  • Compliance ADRs signed
  • Review applicable pre-code evidence
GATE S2 — Post-Code

Quality + Security

  • SAST scan clean
  • OWASP re-verified on shipped code
  • No secrets committed
  • Ponytail audit PASS
  • Cross-tenant access-denial test ✓ (Fix 43C)
  • Jira comment with gate summary
GUARD 1 — Session Guidance

Constraint Drift Guard

  • Calls for reviewing decisions.md at session start
  • HIGH-confidence lessons apply immediately
  • Checks gate_fired_at timestamp (Fix 43A)
  • Absent gate_fired_at → Sprint 0 treatment
  • Architecture decisions bind ALL roles
GUARD 2 — Review Guidance

Bad Loop Guard

  • Requires BOTH: domain keyword + high-risk verb
  • Self-triggering: deploy / release / production
  • Blocked domains: auth, payments, user-data, secrets
  • Blocked verbs: delete, wipe, drop, overwrite, bypass
  • Requests review of high-risk actions
GUARD 3 — Context Guidance

Image Exact-String Guard

  • Instructs agents to re-check exact strings when using compressed context
  • Exact strings (SHAs, camelCase IDs, file:line refs) must be re-verified
  • Historical limited-sample observations are not a current error-rate estimate
  • Check semantic and exact-string accuracy for the actual workload
  • Reported outcomes are historical observations, not a guarantee against future misreads
